# Built-in groom physics support

`Version.json` declares the native groom content guaranteed by the Avatar Studio production target for Unreal 5.8 Windows uploads. The initial contract is `avatar-studio-ue58-windows-groom-v1`; its package inventory and audit provenance are in `resources/groom_runtime_ue58_windows.json`.

This declaration is a supported-target guarantee, not a statement that every Unreal 5.8 project contains these files. Keep the full listed cooked package families available at their original mounts across deployments and rollback targets while the declaration remains published. Cook both built-in solvers explicitly rather than relying on one sample avatar to reference them. Validate the inventory against the packaged runtime before publishing a runtime update. The initial audit checked all eight package headers and export payloads in both Production R5 (HQ-rfctr19) and Preview HQ-rfctr21; real groom simulation remains a separate runtime QA gate. Perforce changelist 3357 on `AvatarStudio_HQ_Rfctr` explicitly retains `/HairStrands/Emitters` in future cooks.

The plugin accepts only this product, service, engine and Windows contract. It keeps the two built-in solver roots shared; custom solver systems and ordinary groom dependencies are still copied. Artifacts record the required contract. Packaging checks the resolver's fresh, checksum-bound version document, and each upload checks the target declaration again. An absent or mismatched contract blocks physics uploads; a downloaded source requirement cannot grant target compatibility.

Publish this declaration only after the target runtime guarantee is in place. Remove it before routing uploads to an incompatible runtime, and publish a new contract for another engine, platform or service. The resource inventory does not authorize changing a user's solver mode or silently disabling simulation.

`project_settings.uploader_utility_plugins` separately enables the installed `Interchange` engine plugin in the minimal cooking project. Newer assets serialize their import node classes in opaque editor data, so ordinary runtime references do not identify this requirement. This utility does not expand the avatar's runtime descriptor or shared-content exemptions. The new optional field keeps older SDKs compatible: their strict legacy `required_plugins` list is unchanged. Enabling only Interchange made the same physics fixture cook pass with zero errors; pre-existing SDK/ACL warnings remained.
